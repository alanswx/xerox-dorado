## 2. What was fixed, and what each one teaches

Five regressions and two input bugs, 2026-07-28..30.

**`0090242` The Alto Executive disk boot was a STALE PACK, not the emulator.**
`3fe8ae1` (2026-06-27) changed `dsk2trident`'s default `--sector-offset` from
1 to 0; the checked-in `chm/diskpacks/games-trident.pack.gz` was never
regenerated, so every sector sat one slot late. Diffing old against new pack
shows it exactly: old slot n+1 == new slot n. Regenerating fixed it with zero
source changes. *Lesson: a checked-in binary that a build step also produces
will rot silently the moment the producer changes. Test the medium before
bisecting the reader.*

**`eb038e4` The cold-Alto init must not fire for a Mesa outload.** `40e6491`
extended the init to real PC `0o2006` whenever `alto_ether_boot` was set, but
that flag only means "Initial netbooted the world" -- equally true of the Mesa
world, where `0o2006` is not EBoot at all. It wiped a running MesaNetExec's
stack and I/O page. Five worlds came back (MesaNetExec, PPong, MazeWar,
PupWatch, TriEx). The gate now keys on the served image's first word, which
`ethernet.c` already decodes: `0o405` = Alto B-format, `0o345` = Mesa outload.
*Lesson: a fact about HOW something loaded is not a fact about WHAT loaded.*

**`56821d4` A standard Pup client gets 512-byte data Pups, not Cedar's 1478.**
Lyric's 4.8 MB sysout retrieve wedged from 2026-07-11: the server sends up to
1,478 bytes (what Cedar advertises as a directly connected host) and only
clamps once the client's allocation is known -- which arrives in its first BSP
ack. The Alto client never gets there; the first data Pup is already oversized,
it drops it, never acks, window fills at `in_flight=8/16`. Honoring the
client's own advertisement is NOT enough: it says 532 and still drops 532.
Measured at 2.5 B cycles by FTP trace lines: 1478 -> 68 wedged, 532 -> 141
crawling, **512 -> 22,809 streaming**.

**`4088e99` / `80c27ff` A painted screen is not a booted world.** Both
frontends left fast-boot as soon as `rendered_px > 700`. MesaNetExec paints
its first herald line (~1,250 px) at ~30 M cycles but reaches its `>` prompt
near 300 M, so it throttled immediately and crawled -- looking hung in the
browser and in SDL. Now a Mesa outload boots in large chunks until 800 M
cycles (SDL adapts 4 M..32 M to the present rate). Alto worlds are untouched:
they paint when they are ready.

**`b31b15c` / `074d28f` / `5673515` The input path — three of my own bugs.**
- `133fbd8` gave a Mesa world the live-input path and seeded the **mouse**
  along with the keyboard. `machine_seed_mouse` writes the ALTO mouse cells,
  which are ordinary VM to a Mesa world; the world stalled at its first herald
  line the moment the host cursor crossed the window.
- With that fixed, browser typing still did nothing: a Mesa world samples its
  keyboard on the display-field cadence and a browser keydown/keyup pair
  arrives faster than that, so both transitions fell between samples. Mesa
  outloads now use the same buffer Cedar uses, drained one transition per
  three fields, paced by cycles.
- `575744b` (my Smalltalk work) wrote the mouse position AND UTILIN at three
  addresses: `0`, `BR031`-relative, `BR036`-relative. Two of those are guesses
  that land wherever the base register points, i.e. in live guest data, so
  every pointer motion scribbled two arbitrary words. One click turned the
  Smalltalk desktop into noise (246,317 px of garbage vs 123,934 healthy).
  Smalltalk boots to exactly the same 124,945 px with the base-0 writes alone,
  so the shotgun bought nothing.

*Lesson, and it cost five rounds of "it still seems hung": every one of these
hid behind a scripted test. Headless never moves a mouse, and the gates typed
with `--key-hold` 1 M..4 M cycles when a display field is 277,778 and a
browser keystroke is shorter than one. The gates exercised a machine no human
ever drives.*

## 3. Open, with repros

### 3.1 Lyric: a click delivers a spurious `?` and inverts the video — NOT a crash

Clicking in the Prompt Window of the restored Lyric desktop makes the Exec
print its `?` help listing (`You are typing at the Exec. Enter <expression>
to evaluate an expression...`) and inverts the screen: desktop stipple and
window backgrounds go black, pixels 208,966 -> 362,313. It reads as a crash
and is not one -- the world is alive and responding to a keystroke nobody
typed.

Reproduce in the browser (headless `--click` does NOT reproduce it, which is
itself a clue):

    make web && (cd web && python3 -m http.server 8765)
    # boot "Lyric — saved Exec (XCL) desktop", click in the Prompt Window

**Prime suspect:** UTILIN carries the mouse buttons AND the Alto's 5-key
keyset in one cell (`machine_seed_utilin`, `0177030-3`, active low, we write
`~(buttons & 07)`). If our button bits land in the wrong position or polarity
for what Interlisp's IOPage expects, Lisp reads a keyset chord -- and keyset
chords generate characters. Check the layout against the Alto Hardware Manual
UTILIN assignment first, then against what the Lisp microcode reads.

### 3.2 Lisp keyboard input never echoes in XCL

Typing `(PLUS 1 2)` into the Exec produces no echo. This is long-standing --
`docs/CONTINUE-HERE.md` calls it "the last interaction gate" -- and today's
key-buffer work does NOT cover it (that covers Cedar and Mesa worlds only).
Independent of 3.1.

### 3.3 Smaller open items

- **Chat (0 px), Clock (0 px), Fly (98 px)** — never diagnosed; Clock is Alto
  B-format, Chat and Fly are Mesa outloads. Likely input-waiting or the
  documented timing class.
- **Cedar cold-boot login is non-deterministic** (28,490 vs 28,494 px from an
  identical binary), so that path cannot be gated byte-exactly. Undiagnosed.
- **`index.html` is not cache-busted.** `index.js`, `index.wasm` and
  `index.data` carry `?v=<build>`, but the HTML that references them does not,
  so a browser holding the page can serve stale HTML. One hard reload fixes it
  per deploy; a proper fix would set a no-cache hint or a versioned entry
  point.

## 4. Tools worth knowing about

- `make verify-input` — pointer motion plus 120,000-cycle keystrokes (shorter
  than a display field). Validated against the bug it exists for: **1,250 px
  at `b31b15c~1` vs 1,573 px fixed**. A gate that cannot fail on its own bug
  is decoration; check this when adding more.
- `--mouse X,Y` — headless pointer MOTION, in eight steps like a hand. Motion
  is its own input path (it sets `mouse_present`); `--click` alone cannot
  catch motion bugs.
- `make verify-lisp` — restores the Lyric XCL desktop, 208,985 px.
- `make run-mesa-netexec`, `run-ppong`, `run-mazewar`, `run-pupwatch`,
  `run-triex`, and `make run-mesa MESA_BOOT=...` — SDL for Mesa worlds.
- SDL prints a progress line every 60 frames (`frame N cyc=... px=...
  chunk=...`) and the window title carries frame/cycles. The browser status
  line carries a live `[N M cycles]` counter. Use them to tell "slow" from
  "stuck" before theorising.
- `DORADO_COMPAT_MD_BYPASS=1` restores the retired same-instruction Md bypass;
  `DORADO_LC5_TRACE` dumps LC=5 sites with their FF field.

## 5. Two methodological traps hit this week

**Do not read a criterion off a log the run is still writing.** Two Lyric
bisects were run against "HEAD produces only 2 FTP trace lines", read from a
partially-written file. The complete file is 68 lines and contains the whole
opening conversation, so the criterion was true on both sides and both
bisects measured noise. Both verdicts were retracted (`e9e96f7`).

**Prefer a criterion with a large numeric margin over a boolean.** `rfc >= 1`
hid a 185x difference (12,613 vs 68 lines) behind a yes.
